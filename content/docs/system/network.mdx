`system.network` gives a Program the web's own `fetch` and `WebSocket`, while
the System checks each destination. It returns a standard `Response` and
`WebSocket`, the same in a Server, a Client, and a Node script.

## Fetch

```ts
const response = await system.network.fetch("https://api.example.com/items", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ name: "Notes" }),
  signal: AbortSignal.timeout(10_000),
})
```

An HTTP error, such as `404`, is a normal `Response`. It rejects only when the
request cannot be made: the network fails, or the destination is not allowed.

## WebSocket

```ts
const socket = await system.network.websocket("wss://example.com/events", ["events.v1"])
socket.addEventListener("message", event => console.log(event.data))
```

A socket opened by a Server or a Node script closes when that Endpoint stops,
or that connection ends. A Client's socket follows its page.

## The network permission

Every request needs a `network` [permission](/docs/system/permissions) that
covers its URL:

| Value | Covers |
| --- | --- |
| `https://api.example.com` | Any path on that host |
| `https://api.example.com/v1/**` | Paths under `/v1/` |
| `https://api.example.com/v1/items` | Exactly that path |
| `https://*.example.com` | Any subdomain, but not `example.com` itself |
| `http://localhost:*` | Any port on `localhost` |
| `wss://example.com` | WebSockets to that host |

`http`, `https`, `ws`, and `wss` are separate: allowing one does not allow the
others. The permission is checked when you call; a response or socket you
already have keeps working if it later changes.

## From the terminal

The terminal reaches the network directly, as its user.
