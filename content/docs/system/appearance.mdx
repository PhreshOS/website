The Appearance is the System's visual values: colors, spacing, corner radius,
shadow, material, motion tempo, the Taskbar, and wallpapers. The Desktop
draws itself with them, and Programs read them to match. There is one, kept by
the System, so every Desktop and every Program sees the same.

## Read it

```ts
const { colors, spacing, radius } = await system.appearance.snapshot()
system.appearance.subscribe("change", appearance => {})   // the whole new value
```

Reading needs no permission. [React UI](/docs/sdks/react-ui) takes the
Appearance directly, so a Program built with it matches the Desktop.

## Light and dark

Values that differ between light and dark have a `light` and a `dark` side:

```ts
colors.light.background
colors.dark.background
```

Each Desktop's own [preference](/docs/desktop/preferences) chooses which one it
shows. The names choose a side; they do not promise which is lighter. When it
matters, compare the colors themselves.

## What it holds

| Value | Light and dark | Holds |
| --- | --- | --- |
| `colors` | Yes | `background`, `foreground`, `default`, `primary`, `secondary`, `success`, `warning`, `danger`, `info` |
| `spacing`, `radius` | No | A base spacing and corner radius, `6` to `18` |
| `shadow` | Yes | `x`, `y`, `blur`, `spread`, `opacity` |
| `material` | Yes | `grain`, `grainAmount`, `backdrop`, `opacity`, `distortion`, `saturation` |
| `tempo` | No | How fast everything moves: `1` is the designed pace, from `1/3` (faster) to `4` (slower) |
| `taskbar` | No | Its `position`, `size`, and whether it lies `overlay` over Windows |
| `wallpapers` | Yes | `signIn` and `desktop`, each an upload's key |

## Motion

The Appearance holds no durations or curves. Each motion is derived from what
moves and how far it goes, and the `tempo` only stretches or shortens time, so
every motion keeps its shape. [Motion](/docs/sdks/react-ui/motion) explains
how.

## Change it

`update()` changes only what you pass, and needs the `appearance`
[permission](/docs/system/permissions):

```ts
await system.appearance.update({ spacing: 14 })
await system.appearance.update({ colors: { dark: { primary: "#f59a62" } }, tempo: 1.5 })
await system.appearance.update({ taskbar: { position: "left", overlay: true } })
```

The whole result is checked and applied at once, so no Desktop shows half a
change: an invalid value changes nothing.

## A wallpaper

Each theme has two wallpapers: `signIn`, behind the sign-in form, and
`desktop`, behind the windows. [Upload](/docs/system/uploads) a file, then use
its key:

```ts
const { file } = await system.uploads.write(image)
await system.appearance.update({ wallpapers: { dark: { desktop: file } } })
```

An image covers the screen; a video plays muted and looping; an HTML page runs
sandboxed, without network. A wallpaper is at most 50 MiB.

The wallpapers the System comes with are uploads too, under keys it keeps,
such as `DESKTOP_DARK_WALLPAPER`: `systemWallpapers` from `@phreshos/core`
names them. Each release puts its own
pictures behind them, so they bring back the release's wallpapers:

```ts
import { systemWallpapers } from "@phreshos/core"

await system.appearance.update({ wallpapers: { dark: { desktop: systemWallpapers.dark.desktop } } })
```

## Without a System

Core has the same rules, to build and check an Appearance offline:

```ts
import { applyAppearanceUpdate, defaultAppearance } from "@phreshos/core"

const next = applyAppearanceUpdate(defaultAppearance, { spacing: 14 })
```

## From the terminal

```sh
phresh appearance get --json
phresh appearance update --value '{"spacing":14}'
phresh appearance wait --event change
```
