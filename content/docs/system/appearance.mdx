Appearance is one set of visual settings shared by the whole System: colors,
spacing, corner radius, shadow, material, motion timing, the Taskbar, and
wallpapers. The Desktop draws itself from it, and Programs can read it so
their interfaces match.

It is stored by the System, so every Desktop and every Program sees the same
values.

```ts
const appearance = await system.appearance.snapshot()

system.appearance.subscribe("change", appearance => applyTheme(appearance))
```

## Read it

`snapshot()` returns the complete current Appearance. `change` delivers the
complete new value each time it changes, never just the part that changed.

```ts
const { colors, spacing, radius } = await system.appearance.snapshot()
const background = colors.dark.background
```

Values that depend on the theme, such as colors, shadow, material, and
wallpapers, have a `light` and a `dark` branch. Which one applies is chosen
by each [Desktop's theme preference](/docs/system/desktop#preferences).

[React UI](/docs/sdks/react-ui) accepts an Appearance directly, so a Program built
with it matches the Desktop without extra work.

## Change it

`update()` changes only the fields you pass and keeps the rest:

```ts
await system.appearance.update({ spacing: 14 })

await system.appearance.update({
  colors: { dark: { primary: "#f59a62" } },
  transaction: { duration: 160 },
})
```

The whole result is validated and applied at once, so no Desktop ever shows a
half-applied change. An invalid value rejects the update and changes nothing.

Changing Appearance requires the `appearance`
[permission](/docs/system/security/permissions).

## What it contains

| Field | Themed | Contains |
| --- | --- | --- |
| `colors` | Yes | `background`, `foreground`, `default`, `primary`, `secondary`, `success`, `warning`, `danger`, `info` |
| `spacing` | No | A base spacing, `6` to `18` |
| `radius` | No | A base corner radius, `6` to `18` |
| `shadow` | Yes | `x`, `y`, `blur`, `spread`, `opacity` |
| `material` | Yes | `grain`, `grainAmount`, `backdrop`, `opacity`, `distortion`, `saturation` |
| `transaction` | No | `duration` in milliseconds and `easing` for visual changes |
| `taskbar` | No | `position`, `size`, `overlay` |
| `desktopWallpaper`, `signInWallpaper` | Yes | An upload key, or `null` for the built-in wallpaper |

Theme names do not promise which color is lighter: a `light` branch may use a
dark background. When your code depends on it, compare the colors themselves.

### Limits

| Value | Range |
| --- | --- |
| `spacing`, `radius` | `6` to `18` |
| Shadow `x`, `y` | `-48` to `48` |
| Shadow `blur` | `0` to `96` |
| Shadow `spread` | `-24` to `24` |
| Shadow `opacity` | `0` to `1` |
| Material `grain`, `grainAmount`, `opacity` | `0` to `1` |
| Material `backdrop` | `0` to `24` |
| Material `distortion` | `0` to `140` |
| Material `saturation` | `1` to `2.6` |
| Transaction `duration` | `0` to `60000` |
| Taskbar `size` | `0` to `100` |

`easing` is `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, or a
cubic Bézier as four numbers.

### Taskbar

| Field | Values |
| --- | --- |
| `position` | `"top"`, `"left"`, `"bottom"`, or `"right"` |
| `size` | Its thickness in pixels |
| `overlay` | `true` hides it at its edge and shows it over Windows when the pointer reaches that edge |

```ts
await system.appearance.update({ taskbar: { position: "left", overlay: true } })
```

## Set a wallpaper

Upload a file, then use its key. Each theme has its own wallpaper:

```ts
const { file } = await system.uploads.write(image)

await system.appearance.update({
  desktopWallpaper: { dark: file },
})
```

`signInWallpaper` works the same way for the sign-in screen. `null` restores
the built-in wallpaper.

| Kind | Formats | Shown as |
| --- | --- | --- |
| Image | Common browser image formats | Covers the screen |
| Video | `mp4`, `ogg`, `ogv`, `webm` | Muted, looping, autoplaying |
| HTML | `html` | A sandboxed page without network access or navigation |

A wallpaper file can be at most 50 MiB. For a solid color, upload a small SVG
or HTML file.

See [Storage](/docs/system/storage#uploads) for uploads.

## Work without a System

Core exports the same rules, so tools can build and validate an Appearance
offline:

```ts
import {
  applyAppearanceUpdate,
  appearanceLimits,
  createAppearanceSnapshot,
  defaultAppearance,
} from "@phreshos/core"

const next = applyAppearanceUpdate(defaultAppearance, { spacing: 14 })
```

## Reference

| Member | Result |
| --- | --- |
| `system.appearance.snapshot()` | The complete Appearance |
| `system.appearance.update(changes)` | Applies the changes; requires `appearance` |
| `system.appearance.subscribe("change", …)` | The complete new Appearance on each change |
| `defaultAppearance`, `appearanceLimits` | Defaults and ranges, from Core |
| `createAppearanceSnapshot()`, `applyAppearanceUpdate()` | Build and update values offline |
