`system.shell()` runs a command in the machine's shell (`/bin/sh`, or `cmd.exe`
on Windows), so pipes and redirections work, and streams what happens:

```ts
for await (const event of system.shell("npm test", { cwd: "/path/to/project" })) {
  if (event.event === "started") console.log("pid", event.pid)
  if (event.event === "output") console.log(event.stream, event.text)
  if (event.event === "exited") console.log(event.exit.code)
}
```

A non-zero exit code is a normal `exited` event. The loop throws only when the
command cannot run at all.

## Options

```ts
system.shell("make build", {
  cwd: "/path/to/project",           // the user's home folder by default
  env: { NODE_ENV: "production" },   // added to the System's environment
  signal: controller.signal,         // stops the command
})
```

## How long it runs

The command lives as long as the loop. Leaving the loop, aborting its
`signal`, or losing the Endpoint or connection that started it stops the
command and every process it started.

A shell command is not a [Process](/docs/program/processes): it has no
Endpoints, no Service, and no place on the Desktop. Use a Process when the work
belongs to a Program.

## Permission

A command can do anything its user can, so a Program needs the `all`
[permission](/docs/system/permissions). A Node script running as the owner
needs none.

## From the terminal

The terminal is a shell already.
