The Desktop is the System's graphical interface. You open it in a browser, and
it shows each running Client as a Window, alongside the Taskbar and Start
Menu.

The Desktop is a view, not the place where Programs live. The System keeps
running Programs and their Window state; a Desktop displays them. You can open
the same System in several browsers at once, and each one is a separate
Desktop showing the same Windows.

```ts
import { context, desktop } from "@phreshos/client"

await context.window.setTitle("Notes")       // this Client's Window
const size = await desktop.viewport.size()   // the Desktop around it
```

## Windows

Every running [Client Endpoint](/docs/runtime/endpoints#the-client) is shown as a
Window. A person can move, resize, snap, minimize, and maximize it through the
Desktop.

Closing a Window exits its Process, including its Server. To keep work running
without a Window, stop only the Client:

```ts
await process.client.stop()
```

## Where Windows are

Standard Windows live on a plane larger than the screen. The plane is five
views across and five down, each view the size of the whole Desktop. Zero is
the center of the middle view, so a Desktop that has not moved shows exactly
that view.

A Window's position is its top-left corner on this plane: `{ x: 0, y: 0 }` puts
the corner at the center, and negative values go left and up. Positions and
sizes accept pixels or relative values. A number is always pixels; strings
express a share of the view:

```ts
await context.window.move({ x: -450, y: -320 })            // a 900 × 640 Window, centered
await context.window.move({ x: "-1/2", y: "-1/2" })        // the top-left corner of the view
await context.window.move({ x: "100% - 450", y: -320 })    // centered in the view to the right
await context.window.resize({ width: "1/2", height: "100%" })
```

Each Desktop resolves relative values against its own size, so the same Window
fits every screen it is shown on, and a view on the plane is one screen on every
Desktop.

### The view

Each Desktop shows one view of the plane at a time, and can move it: the **Map**
in the Taskbar shows every Window where it is, and moving across it moves the
view. Pressing a Window in the Map brings the view to the view the Window is
in, and dragging it moves
the Window to another view. Pressing a Window in the Taskbar does the same: the
view comes to the view the Window is in, and the Window comes to the front. If
it is already the front one, the press minimizes it. Holding a drag over it
takes you there too, so the drop can land in it.

A Window's menu is the same in the Taskbar and in the Map: **Go to** brings the
view to the view the Window is in, **Bring here** moves the Window into the view on screen,
keeping its place within a view, and the rest show, minimize, maximize, restore,
or close it where it is.

This makes the plane a set of workspaces that continue into each other: one
view for a task, another for the next, or one where an agent works while you
watch by moving there.

Where a Desktop looks belongs to that Desktop alone. It starts at the center
each time the Desktop opens, is never stored, and another Desktop showing the
same System can look elsewhere. The System records only the Windows' positions;
it knows nothing about views.

A maximized Window fills the view it is in, the one its center is in, without
changing its stored geometry. Each view can have its own maximized Window, and
moving one's geometry to another view takes its maximized state there.

### What the Desktop shows

The System records Window values as they are given; the Desktop decides how to
show them:

- A Window recorded beyond the plane is shown at its edge, and one larger than
  two views in either direction is shown at that size.
- No Window is shown smaller than 260 × 160 pixels, as far as the screen allows.
- An edge on the Desktop's own edge is drawn clear of it by the Appearance
  spacing, and clear of the Taskbar on its side, and Windows side by side keep
  the same gap between them. Margins and gaps are drawn, never recorded, so a
  maximized Window is simply the whole view.
- A Window moves visibly only when both where it was and where it goes are on
  the screen. Moved from or to another view, it is simply there.

None of this changes what is stored. Only moving or resizing the Window records
new values, and those are what the Desktop showed. A Window placed in another
view is recorded in views, such as `"100% - 450"` one view to the right, so it
stays in that view on a Desktop of any size.

A Window's launch, then its Program, say its size and position. What neither
says, the System fills the same way in every layer: 500 × 500 pixels, centered
on zero. The Start Menu launches with what it sees instead: a Window whose
Program declares no size gets a square three fifths of the view's shorter side,
and one that declares no position opens in the middle of the current view,
stepped slightly from the Windows already there. See
[Program configuration](/docs/sdks/core/program-configuration#the-window).

## Control your Window

A Client reaches its own Window through `context.window`. Other code reaches
it through `process.client.window`.

```ts
await context.window.setTitle("Notes")
await context.window.resize({ width: 900, height: 640 })
await context.window.move({ x: -450, y: -320 })
await context.window.setGeometry({ x: -450, y: -320, width: 900, height: 640 })
await context.window.maximize()
await context.window.minimize()
await context.window.setHeader(false)   // hide the Desktop's title bar
await context.window.raise()            // bring it to the front
```

`setGeometry()` changes position and size in one step. Minimizing and
maximizing keep the stored geometry, so restoring returns the Window where it
was.

Read the current state, or follow its changes:

```ts
await context.window.size()      // also title, header, position,
await context.window.maximized() // minimized, front, and layer

context.window.subscribe("resize", size => {})
context.window.subscribe("move", position => {})
```

| Event | When |
| --- | --- |
| `move`, `resize` | Position or size changed |
| `minimize`, `maximize` | Minimized or maximized state changed |
| `changeTitle`, `changeHeader` | Title or header visibility changed |
| `front` | The Window became, or stopped being, the front one in its layer |

The Window belongs to the current run of the Client. Each time the Client
starts, the Window starts fresh from the Program's declaration and the start
settings. Changing a Window while its Client is stopped rejects.

## Draw your own title bar

With `setHeader(false)`, the Program draws its own title bar. To let people
drag the Window by it, hand the drag to the Desktop once the pointer starts
moving:

```ts
const move = context.presentation.beginMoveGesture({
  origin: { x: pressedX, y: pressedY },  // where the pointer went down
  point: { x: currentX, y: currentY },   // where it is now
})

await move.ready     // the Desktop now follows the pointer
await move.finished  // the drag ended
```

After `ready`, release your own pointer capture. `move.cancel()` ends the drag
early.

## Layers

The Desktop stacks five layers, from back to front:

| Layer | What goes there | Who draws and places it |
| --- | --- | --- |
| `wallpaper` | One full-screen background | The Desktop |
| `under` | Content behind the Windows, such as desktop widgets | The Program |
| `window` | Standard Windows. This is the default | The Desktop |
| `over` | Content above the Windows, such as overlays and notifications | The Program |
| `shell` | The System interface: Taskbar, Start Menu, dialogs | The Program |

Choose a layer when starting the Client:

```ts
await program.createProcess({ client: { layer: "over" } })
```

Every layer covers the whole Desktop. Only the `window` layer is a plane of
views; the others stay where the screen is. Raising a Window only reorders it
within its own layer. Any layer other than `window` requires the `layers`
[permission](/docs/system/security/permissions).

**Wallpaper** holds one Client. Starting another wallpaper Client exits the
Process of the current one.

**Shell** belongs to one Program at a time, which may show any number of
Clients there. When another Program claims the shell, the System exits every
Process of the previous one. While no Program occupies it, the Desktop shows
its built-in Taskbar, Start Menu, and dialogs. Replacing the shell changes
only the interface: the System keeps owning Programs, Processes, and
permissions.

## Your drawing

`context.window` is the Window the System keeps: values every Desktop follows,
which may be shares of the view. `context.presentation` is how the Client is
actually drawn on this Desktop, in pixels, with positions counted from the
center of the whole Desktop to the drawing's top-left corner. The drawing is
the Client's own frame, so in a standard Window it leaves out the title bar.

Every layer reads its drawing and hears it change:

```ts
await context.presentation.position()      // { x: -480, y: -300 }
await context.presentation.size()          // { width: 960, height: 600 }
await context.presentation.front()         // the front of its layer
await context.presentation.interactive()   // clicks reach it
await context.presentation.surface()       // what the Desktop paints behind it

context.presentation.subscribe("resize", size => {})
```

| Event | When |
| --- | --- |
| `move`, `resize` | The drawing moved or changed size |
| `front` | It became, or stopped being, the front of its layer |
| `changeInteractive` | Clicks began, or stopped, passing through it |
| `changeSurface` | The surface behind it changed |

Reads and events tell the drawing as it is at the moment: while the Desktop
carries it with the pointer, and along a motion, not only at rest. An effect
that only changes how it looks, such as the scale a Window enters with, moves
nothing and is not a change. The size is the frame's own, the same as
`innerWidth` and `innerHeight` inside the document.

In React, `usePresentationState(context.presentation)` reads the drawing and
follows it.

### Draw outside standard Windows

In `under`, `over`, and `shell`, the Desktop never draws the Client on its own.
The Client starts at zero size, and the Program writes its drawing itself, in
pixels:

```ts
await context.presentation.setGeometry({ x: -360, y: -240, width: 720, height: 480 })   // centered
await context.presentation.raise()
```

Writes take effect at once. Move them with the Appearance timing, or your own:

```ts
await context.presentation.transaction().resize({ width: 360, height: 240 })
await context.presentation.transactionAndWait(300).move({ x: 0, y: 0 })
```

`transaction()` resolves once the Desktop accepts the change;
`transactionAndWait()` resolves when the motion ends. A share of the screen is
the Program's to work out, from `desktop.viewport`.

The Desktop can paint a surface behind the Client, using the System's
Appearance:

```ts
await context.presentation.setSurface(true)
await context.presentation.setSurface({ radius: 16, color: "background" })
await context.presentation.setSurface(false)   // no surface
```

To let clicks pass through to what is behind it:

```ts
await context.presentation.setInteractive(false)
```

`context.window` still holds the Window's values in these layers, and its
events still arrive; the Program decides what they mean for its drawing, such
as what maximizing does, and applies that on every Desktop showing it.

A standard Window is drawn by the Desktop from its Window, and the wallpaper
by the Desktop alone, so both refuse writes. A move gesture works in every
layer but the wallpaper: in `under`, `over`, and `shell` the Desktop carries
the drawing with the pointer, and the Program hears where it went.

| Presentation operation | `window` | `under`, `over`, `shell` | `wallpaper` |
| --- | --- | --- | --- |
| `layer()`, `position()`, `size()`, `front()`, `interactive()`, `surface()`, `subscribe()` | Yes | Yes | Yes |
| `beginMoveGesture()` | Yes | Yes | No |
| `move`, `resize`, `setGeometry`, `setSurface`, `transaction` | No | Yes | No |
| `raise`, `setInteractive` | No | Yes | No |

Unavailable operations reject.

## Read the Desktop around you

A Client can read the Desktop that contains it through the `desktop` import:

```ts
import { desktop } from "@phreshos/client"

const size = await desktop.viewport.size()       // { width, height } in CSS pixels
const offset = await desktop.viewport.offset()   // { x, y }
desktop.viewport.subscribe("resize", size => {})
desktop.viewport.subscribe("move", offset => {})
```

The offset is the point of the plane shown at the center of this Desktop: zero
until the view moves, then how far it moved. A Program that places its own
Windows can use it to open them where the person is looking.

A Program can also move the view, for example to take the person to a view it
arranged:

```ts
await desktop.viewport.move({ x: 1440, y: 0 })   // show this point of the plane at the center
```

The Desktop keeps the view on the plane, and every Client following it hears
`move`. Reading the view is always allowed; moving it requires the
`desktopViewport` permission, since it changes what the person is looking at.

### Preferences

Each Desktop has its own preferences, stored in its browser:

| Preference | Values |
| --- | --- |
| `theme` | `"light"` or `"dark"` |
| `animations` | `true` or `false` |
| `scale` | `0.5` to `2`, `1` by default |

```ts
const { theme } = await desktop.preferences.snapshot()
desktop.preferences.subscribe("change", preferences => {})

await desktop.preferences.update({ theme: "dark" })
await desktop.preferences.update({ scale: "default" })   // back to the default
```

`"default"` follows the operating system for theme and animations. Reading
preferences is always allowed; changing them requires the
`desktopPreferences` permission.

Preferences choose between light and dark and how things move. What light and
dark look like is set System-wide by [Appearance](/docs/system/appearance).

### Connection

`desktop.connection()` returns the browser
[Connection](/docs/system/security/authentication) showing this Desktop. It
requires the `desktopConnection` or `authentication` permission.

## From the CLI

```sh
phresh window inspect --process main --program notes
```

## Permissions

| Permission | Allows |
| --- | --- |
| `layers` | Starting a Client in `wallpaper`, `under`, `over`, or `shell` |
| `desktopPreferences` | Changing Desktop preferences |
| `desktopViewport` | Moving this Desktop's view |
| `desktopConnection` | Reading this Desktop's Connection |

See [Permissions](/docs/system/security/permissions).
