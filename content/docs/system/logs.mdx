PhreshOS keeps two kinds of logs:

- **Program logs**: everything a Program's Endpoints print, such as Server
  output and Client console messages, in `program.logs`;
- **System log**: events the System itself records, such as an Endpoint
  crashing, in `system.logs`.

Both are SQLite tables you can query, and both let you follow new records as
they arrive.

```ts
const errors = await program.logs.query(
  "SELECT * FROM logs WHERE kind = ? ORDER BY createdAt DESC LIMIT 20",
  ["error"],
)

program.logs.subscribe("log", record => console.log(record.content))
```

## Query past records

`query()` runs one SQL statement against the `logs` table. Pass values as
parameters, or use a template literal, whose values become parameters:

```ts
await system.logs.query("SELECT * FROM logs WHERE level = ?", ["error"])

const since = Date.now() - 60_000
await program.logs.query`SELECT * FROM logs WHERE createdAt > ${since}`
```

Logs are read-only: statements that change them reject.

## Follow new records

```ts
const stop = system.logs.subscribe("log", record => {
  if (record.level === "error") notify(record.content)
})
```

A record is delivered only after it is stored, so it is already queryable
when you receive it. Subscribing shows new records only; query to see earlier
ones.

## Program records

Each line an Endpoint prints becomes one record:

| Field | Contains |
| --- | --- |
| `createdAt` | When it was captured, in Unix milliseconds |
| `process` | The Process identity |
| `source` | `"client"` or `"server"` |
| `kind` | The console method (`log`, `info`, `warn`, `error`, `debug`), the stream (`stdout`, `stderr`), or `exit` |
| `content` | The text |

Every Endpoint exit is also recorded, with `kind: "exit"`.

## System records

| Field | Contains |
| --- | --- |
| `createdAt` | When it happened, in Unix milliseconds |
| `level` | `"debug"`, `"info"`, `"warning"`, or `"error"` |
| `source` | The part of the System that recorded it |
| `kind` | A stable name for the event, such as `unexpectedServerEndpointExit` |
| `content` | A human-readable description |
| `data` | Details as JSON, or `null` |

In SQL, `data` is JSON text, so you can use SQLite's JSON functions:

```ts
await system.logs.query(
  "SELECT json_extract(data, '$.program.identity') AS program FROM logs WHERE kind = ?",
  ["unexpectedServerEndpointExit"],
)
```

A crashing Server appears in both logs: as an `exit` record in its Program's
log, and as an error in the System log.

The built-in Shell shows new System errors as they happen. They stay in the
log whether or not anything shows them.

## How long records are kept

Each log keeps its newest 20,000 records and removes older ones. Program logs
are deleted with the Program's storage; see
[Storage](/docs/system/storage#what-happens-to-the-data).

## Permissions

| Log | Requires |
| --- | --- |
| `program.logs` | Access to that Program: your own, or others through `programs` |
| `system.logs` | The `logs` permission |

A Node script connected as the owner can read both. See
[Permissions](/docs/system/security/permissions).

## Reference

| Member | Result |
| --- | --- |
| `program.logs.query(statement, values?)` | Past records of a Program |
| `program.logs.subscribe("log", …)` | New records of a Program |
| `system.logs.query(statement, values?)` | Past System records |
| `system.logs.subscribe("log", …)` | New System records |
