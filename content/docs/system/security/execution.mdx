---
title: Endpoint execution
description: How a Server and a Client run, and what each mode can reach on its own.
---

A Program chooses how its Server and Client run. The choice changes what the
code can reach **on its own**, outside the System API. It never changes the
SDK, the Endpoint contract, or what the System allows through
[permissions](/docs/system/security/permissions).

## Server modes

A Server declares exactly one of three modes in its
[configuration](/docs/sdks/core/program-configuration):

| Mode | Runs | Can reach on its own |
| --- | --- | --- |
| `command` | Any operating-system command, such as a Python or Go program | Everything the user running PhreshOS can |
| `worker` | A JavaScript module in a Node.js Worker | Everything Node.js can |
| `sandbox` | A bundled JavaScript module in a contained runtime | Nothing: only the System API |

```ts title="phresh.config.ts"
server: { location: "dist/server", worker: "main.js" }
server: { location: "dist/server", command: "./server" }
server: { location: "dist/server", sandbox: "main.js" }
```

All three use the same Server SDK. A `sandbox` Server has no file, network,
or process access of its own, so everything it does goes through the System
and its permissions. Use it when the owner should be able to see and control
everything the Program does.

## Client modes

A Client runs as a page inside the Desktop. By default it runs in a
sandboxed frame, which allows scripts and forms but gives the page no origin
of its own:

```ts title="phresh.config.ts"
client: { location: "dist/client" }                  // sandboxed, the default
client: { location: "dist/client", sandbox: false }  // an ordinary frame
```

Without an origin, browser storage such as `localStorage`, `IndexedDB`, and
cookies is not available. Keep data with the System instead, in
[`program.store` or `program.data`](/docs/system/storage), where every Desktop and
the Server can reach it.

`sandbox: false` gives the page the rights of a normal page from the Desktop's
origin. Use it only when the Client needs browser features the sandbox
blocks.

In both modes, the Client uses the same Client SDK, and its System access is
decided by the Program's permissions.
