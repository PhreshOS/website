title: Overview
description: Who can use the System, what Programs may do through it, and what their code can reach on its own.
---

PhreshOS security answers three separate questions:

| Question | Answered by |
| --- | --- |
| Who is using the Desktop? | [Authentication](/docs/system/security/authentication): the owner signs in, and Sessions keep browsers signed in |
| What may a Program do through the System? | [Permissions](/docs/system/security/permissions): declared by the Program, decided by the owner |
| What can a Program's code reach without the System? | [Endpoint execution](/docs/system/security/execution): the mode each Server and Client runs in |

Each one covers something the others do not:

- Signing in gives a person the Desktop, not any authority to Programs.
- Permissions limit what a Program does **through the System**. They cannot
  take away what its runtime already allows, such as a `worker` Server
  reading files with Node.js.
- An execution mode limits what code can reach **on its own**. It never grants
  anything through the System.

To keep a Program fully under the owner's control, run its Server in
`sandbox` mode and its Client in the default sandboxed frame. Then everything
it does outside its own code goes through permissions.

Node scripts and the CLI connect directly as the owner of the machine, through
a local socket (a named pipe on Windows). They are fully trusted and need
neither a Session nor permissions.
