`phresh describe` returns the definition of a command as data: its name,
aliases, arguments, options, examples, and output. Tools and agents use it to
learn the CLI without parsing `--help` text.

```sh
phresh describe                        # the top-level commands
phresh describe process create         # one command
phresh describe --all --json           # every command, as JSON
```

It works without a running System.

## Where an agent starts

`phresh skill` explains PhreshOS to an agent before its first command: what the
System is, that `phresh` acts with the owner's authority, how Programs offer
what they do, and where to find the documentation. The top-level `--help`
points agents to it.

```sh
phresh skill
```

## What a description contains

- the command path and its aliases, such as `set-geometry` for `setGeometry`;
- its arguments and options, with whether each is required, repeatable, its
  allowed choices, and its default;
- guidance and examples;
- whether it needs a running System;
- the shape of its output, and its subcommands.

`--help` is generated from the same definitions, so both always agree.

## CLI commands and System operations

`phresh describe` covers the commands of the CLI. The operations of the System
itself are described by [Execute](/docs/sdks/core#execute):

```sh
phresh operation list
phresh operation describe --domain endpoint --operation ask
```

The runtime commands are built from those operations, so their descriptions
match.
