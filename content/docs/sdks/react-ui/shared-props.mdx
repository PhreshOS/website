---
title: Shared props
description: The three rules that give every component the same props, and how component families are built.
---

Three rules hold across the library. Learn `Button`, `Input`, and `Select`,
and you already know how to use almost everything else.

## 1. Everything painted takes the same props

Any component that draws a Surface accepts:

| Prop | Sets |
| --- | --- |
| `color` | Its color, by role and level. See [Color](/docs/sdks/react-ui/color) |
| `size` | Its size. See [Size and radius](/docs/sdks/react-ui/size-and-radius) |
| `radius` | Its corners |
| `material` | How much material is drawn. See [Surface](/docs/sdks/react-ui/components/surface#material) |
| `disabled` | Off: cannot be focused or used |
| `className`, `style` | Your own styles, which always win over React UI's |

```tsx
<Button color="primary" size="large" radius="full">Install</Button>
```

## 2. Everything that holds a value is a field

Text fields, selects, checkboxes, switches, sliders, and date fields share one
shape:

| Prop | Does |
| --- | --- |
| `label` | The visible label |
| `description` | Help text below the field |
| `errorMessage` | Shown when `invalid` |
| `invalid`, `required`, `readOnly`, `disabled` | Its state |
| `value`, `onChange(value)` | A value you control |
| `defaultValue` | A starting value the field keeps itself |
| `name` | Its name when submitted in a form |

```tsx
<Input
  label="Email"
  description="Used only for sign-in."
  invalid={!valid}
  errorMessage="Enter a valid email."
  value={email}
  onChange={setEmail}
/>
```

Pass `value` and `onChange` to own the value; pass `defaultValue`, or
nothing, to let the field keep it. Checkbox and Switch use `checked` and
`defaultChecked`, since their value is on or off.

Without a visible label, name the field with `aria-label`.

## 3. Every collection is made of Items

Select, ComboBox, ListBox, Menu, Tabs, Table, Tree, and Accordion are written
the same way: the family, then its items, each with a string `id`:

```tsx
<Select label="Program" value={program} onChange={setProgram}>
  <Select.Item id="notes">Notes</Select.Item>
  <Select.Item id="tilo" disabled>Tilo</Select.Item>
</Select>
```

- **Selection** is the `id` of the selected item, or a list of them when
  several can be selected.
- **Actions** report the `id` through `onAction(id)`.
- **A disabled item** has `disabled` on the item itself.

RadioGroup is the one exception: its items use `value`, because that is what a
form submits.

## Families

A component with parts exposes them as properties of the component itself, and
the parts work only inside it:

```tsx
<Dialog>
  <Dialog.Trigger>Rename</Dialog.Trigger>
  <Dialog.Backdrop>
    <Dialog.Content>
      <Dialog.Title>Rename note</Dialog.Title>
      …
    </Dialog.Content>
  </Dialog.Backdrop>
</Dialog>
```

Overlays are built the same way:

| Part | Owns |
| --- | --- |
| The root, such as `Dialog` | Whether it is open |
| `Trigger` | What opens it |
| `Content` | The floating Surface |
| Your content | What is shown inside |

Focus, keyboard handling, closing, and entrance and exit animations belong to
the component; you do not wire them up.

## Pressing

Buttons and other pressable parts use `onPress`, which works the same for
mouse, touch, and keyboard:

```tsx
<Button onPress={save}>Save</Button>
```

`pending` keeps a Button focusable but prevents presses while something runs;
`disabled` removes it from focus entirely.
