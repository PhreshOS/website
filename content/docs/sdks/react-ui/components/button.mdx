Use `Button` when pressing something does something: save, open, confirm.

```tsx
<Button color="primary" onPress={save}>Save</Button>
```

`onPress` fires for a click, a tap, and Enter or Space alike, so you need no
separate keyboard handling.

## Links

When pressing a Button takes the person somewhere, give it an `href`. It then
renders a real `<a>`, so browsers can open it in a new tab and search engines
can follow it. It looks and behaves like any other Button:

```tsx
<Button href="/blog">Read the blog</Button>
<Button href="https://github.com/PhreshOS" target="_blank" rel="noopener">Source</Button>
```

A link accepts `target`, `rel`, `download`, and the other link attributes, but
not `pending` or `type`. A disabled link has no destination.

Links inside your app, such as `/blog`, go through the `navigate` you give
[`UIProvider`](/docs/sdks/react-ui/setup#links), so your
router can follow them without a page load.

## Color

A Button is neutral (`default`) unless you give it a meaning:

```tsx
<Button>Cancel</Button>
<Button color="primary">Install</Button>
<Button color="danger">Delete</Button>
<Button color="danger:soft">Remove</Button>
```

Use `primary` for the one main action on a screen. The text color, hover,
press, and focus ring follow from the color. See
[Color](/docs/sdks/react-ui/color).

## While something runs

`pending` shows a [Spinner](/docs/sdks/react-ui/components/spinner) in place of
the content while the work the Button started runs. The Button keeps its size
and its name, ignores presses, and stays focusable, so focus does not jump away
mid-action. `disabled` removes it from focus entirely.

```tsx
<Button color="primary" pending={saving} onPress={save}>Save</Button>

<Button disabled>Unavailable</Button>
```

## Depth

A Button is raised, since it stands out as something you act on. `depth="flat"`
keeps its color but lets it sit level with what is around it. Use it where many
Buttons share a place and one of them should stand out, such as the active item
of a bar:

```tsx
<Button depth={active ? "raised" : "flat"} color={active ? "primary:soft" : undefined}>
  {name}
</Button>
```

`depth="none"` makes a quiet Button: nothing is drawn until it is hovered or
pressed, so it reads as part of the text or the place around it. Use it for
actions that belong to what they sit in rather than standing apart, such as a
step of a path that opens a menu, or an option at the end of a list:

```tsx
<Button depth="none" size="xsmall" onPress={showHidden}>Show 12 hidden</Button>
```

## Icons and forms

A Button that holds only an icon takes `iconOnly`: it is square, as wide as
it is tall, instead of padding its sides for text. With no text to name it, it
needs `aria-label` for screen readers:

```tsx
<Button iconOnly aria-label="Close" onPress={close}><CloseIcon /></Button>
```

A Button is `type="button"` by default. Set `type="submit"` to submit a form.

## Props

| Prop | Default | Sets |
| --- | --- | --- |
| `onPress` | — | What happens when pressed |
| `color` | `"default"` | Its color |
| `size` | `"medium"` | Its size |
| `iconOnly` | `false` | Square, for a Button holding only an icon |
| `depth` | `"raised"` | `flat` keeps its color level with what is around it, without a shadow; `none` draws nothing until it is hovered or pressed |
| `radius` | Scaled to its size | Its corners |
| `material`, `shadow` | `"basic"`, the Appearance shadow | Its Surface |
| `href` | — | Where it goes; renders an `<a>` |
| `pending` | `false` | Show a Spinner in place of the content, ignore presses, keep focus |
| `disabled` | `false` | Off |
| `type` | `"button"` | The native button type; not with `href` |
