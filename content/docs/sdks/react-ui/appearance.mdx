title: Appearance
description: Give components their visual values, preferences, and text direction.

Every React UI component reads three things from its surroundings:

| | Is | Default |
| --- | --- | --- |
| **Appearance** | The visual values: colors, spacing, radius, shadow, material, timing | `defaultAppearance` |
| **Preferences** | `theme` (`"light"` or `"dark"`) and `animations` | The browser's settings |
| **Direction** | `"ltr"` or `"rtl"` | The document's `<html dir>` |

With no setup, components use the defaults. `UIProvider` changes any of them
for everything inside it:

```tsx
import { UIProvider } from "@phreshos/react-ui"

<UIProvider
  appearance={{ radius: 14 }}
  preferences={{ theme: "dark" }}
  direction="rtl"
>
  <App />
</UIProvider>
```

## Change the Appearance

`appearance` takes only the values you want to change; everything else comes
from the nearest outer provider, or the default:

```tsx
<UIProvider appearance={{ spacing: 14, colors: { light: { primary: "#3f7de0" } } }}>
  <App />
</UIProvider>
```

Inside PhreshOS, pass the System's Appearance so the Program matches the
Desktop. React UI uses the visual values and ignores the rest:

```tsx
import { system } from "@phreshos/client"
import { SystemProvider, useSystemAppearance } from "@phreshos/react"

function Themed({ children }) {
  return <UIProvider appearance={useSystemAppearance()}>{children}</UIProvider>
}

<SystemProvider system={system}>
  <Themed><App /></Themed>
</SystemProvider>
```

`useSystemAppearance()` follows every change, so the Program updates with the
Desktop. See [React providers](/docs/sdks/react/providers).

What the Appearance contains and its limits are described in
[System Appearance](/docs/system/appearance#what-it-contains).

## Choose light or dark

```tsx
<UIProvider preferences={{ theme: "dark" }}>…</UIProvider>
<UIProvider preferences={{ animations: false }}>…</UIProvider>
```

Leave `preferences` out to follow the browser: `theme` follows its light or
dark setting, and `animations` turns off when it asks for reduced motion.

The theme picks the `light` or `dark` branch of each Appearance value.
Everything else, such as which way a recessed Surface darkens, is derived from
the colors themselves, so a dark palette in the `light` branch still looks
right.

With `animations: false`, every change happens immediately. The Appearance is
unchanged.

### Give the page the theme

`DocumentTheme` writes the theme of the nearest `UIProvider` into the page's
`<meta name="color-scheme">`, before the browser paints, and follows every
change. It renders nothing. Place it once, where the theme that owns the page
is provided:

```tsx
import { DocumentTheme, UIProvider } from "@phreshos/react-ui"

<UIProvider preferences={preferences}>
  <DocumentTheme />
  <App />
</UIProvider>
```

A Program needs it: the browser paints a frame opaque when the color scheme of
the page inside differs from the frame's, instead of letting the Desktop show
through. The System serves a Program's page already declaring the Desktop's
theme, so the page is right from its first paint; `DocumentTheme` keeps it
right when the theme changes. A page that declares its own `color-scheme` keeps
it, so a Program's `index.html` leaves it out.

Without a `UIProvider` above it, it follows the browser's theme, like every
component.

## Set the text direction

```tsx
<UIProvider direction="rtl">
  <App />
</UIProvider>
```

With a direction, components lay out, place popovers, and handle arrow keys
for that direction. Without one, they follow `<html dir>`. The provider adds
no layout box of its own.

## Links inside your app

A Button with an `href` is a real link. Give the provider your router's
`navigate`, and links inside your app go through it instead of reloading the
page:

```tsx
"use client"
import { useRouter } from "next/navigation"

function Providers({ children }) {
  const router = useRouter()
  return <UIProvider navigate={href => router.push(href)}>{children}</UIProvider>
}
```

Links to other sites, links with a `target`, and clicks with a modifier key
are left to the browser.

## Nesting

Providers nest, and each property is inherited separately. A provider with no
props changes nothing.

```tsx
<UIProvider preferences={{ theme: "dark" }}>
  <Sidebar />
  <UIProvider appearance={{ spacing: 8 }}>
    <DenseTable />   {/* dark, with tighter spacing */}
  </UIProvider>
</UIProvider>
```

## Read the values

For your own components, read what React UI uses:

```tsx
import { useAppearance, usePreferences, useThemedValue, useDirection } from "@phreshos/react-ui"

const appearance = useAppearance()                    // the complete Appearance
const { theme, animations } = usePreferences()
const colors = useThemedValue(appearance.colors)      // the branch for the current theme
const direction = useDirection()
```

`useBrowserPreferences()` returns the browser's own settings, whatever any
provider says.

## Reference

| Export | Result |
| --- | --- |
| `UIProvider` | Sets `appearance`, `preferences`, `direction`, and `navigate` for its children |
| `defaultAppearance`, `appearanceLimits` | The default values and their ranges |
| `useAppearance()` | The Appearance in effect |
| `usePreferences()` | The preferences in effect |
| `useBrowserPreferences()` | The browser's preferences |
| `useThemedValue(value)` | The branch of a themed value for the current theme |
| `useDirection()`, `useDocumentDirection()` | The direction in effect, and the document's |
