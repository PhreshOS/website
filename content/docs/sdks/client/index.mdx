`@phreshos/client` is the SDK for a Program's
[Client Endpoint](/docs/runtime/endpoints#the-client): the web page shown in a
Desktop Window. It gives that page access to its Program, its Server, its
Window, the Desktop around it, and the System.

`@phreshos/core` is a peer dependency, so your app and the SDK share the same
Program, Process, and other classes.

## Three entry points

```ts
import { context, desktop, system } from "@phreshos/client"
```

| Import | Is | Use it for |
| --- | --- | --- |
| `context` | This Client, seen from the inside | Its Program, Process, options, messages, Server, and Window |
| `desktop` | The Desktop showing this Client | Its size, preferences, and browser Connection |
| `system` | The whole System | Everything else: Programs, Processes, storage, network, and more |

They are separate because they belong to different owners: the Client belongs
to its Program, the Desktop to the browser showing it, and the System to
everyone.

## Talk to your Server

`context.server` is the Server of the same Process:

```ts
const notes = await context.server.ask("notes.list")
context.server.publish("notes.refresh")
context.server.subscribe("notes.changed", notes => render(notes))
```

See [Communication](/docs/runtime/communication). With React, use
[`useSubscribe`](/docs/sdks/react) to follow events in a component.

## Know where you are

```ts
const program = await context.program()
const process = await context.process()
const document = await context.options("document")
```

Messages sent to this Client arrive through `context.subscribe()`.
`context.publish()` announces something to anyone listening to this Client.
See [Context](/docs/runtime/context).

## Control your Window

```ts
await context.window.setTitle("Notes")
await context.window.resize({ width: 900, height: 640 })
```

`context.window` is the Window itself; `context.presentation` is how this
Desktop shows it, for custom title bars and Clients outside standard Windows.
See [Desktop](/docs/system/desktop).

## Read the Desktop

```ts
const { size } = await desktop.viewport.snapshot()
desktop.viewport.subscribe("resize", ({ size }) => layout(size))

const { theme, animations, scale } = await desktop.preferences.snapshot()
desktop.preferences.subscribe("change", preferences => apply(preferences))
```

By default, `theme` follows the browser's light or dark setting, `animations`
turns off when the browser asks for reduced motion, and `scale` is `1`.
Changing the scale also changes the viewport size the Client sees. See
[Preferences](/docs/system/desktop#preferences).

## Use the System

`system` is the same in a Client as everywhere else:

```ts
const programs = await system.program.list()
const response = await system.network.fetch("https://api.example.com/items")
```

What it can see and do follows the Program's
[permissions](/docs/system/security/permissions), which the Client and Server
share. A Client can check and request them:

```ts
if (!await context.permissions.allows("uploads")) {
  await context.permissions.request("uploads")
}
```

A request ends with `null` if this Client stops before the owner decides.

## The browser sandbox

By default the Client runs in a sandboxed frame without an origin of its own,
so `localStorage`, `IndexedDB`, and cookies are not available. Use
[`context.memory`](/docs/runtime/endpoints#client-memory) for state shared across
reloads of one Client run, or [`program.store` or `program.data`](/docs/system/storage)
for durable data. See
[Endpoint execution](/docs/system/security/execution#client-modes).
