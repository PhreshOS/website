Endpoints talk in two ways: **publish** announces something with no reply;
**ask** waits for exactly one answer. The same operations work between the
two sides of a Process, between Processes, and through
[Services](/docs/program/services). You never deal with frames, workers, or
connections.

## Who receives

The handle you use decides:

| Handle | Reaches |
| --- | --- |
| `context` | Anyone listening to you |
| `process.server`, `process.client` | That Endpoint |
| A Service | The Endpoint offering it |

## Publish

```ts
process.client.publish("theme.changed", { dark: true })   // to that Client
context.publish("ready")                                  // from you
```

Publishing returns at once. If nothing listens, or the destination is not
running, the message is lost.

## Listen

Inside an Endpoint, messages sent to you arrive through `context`, with who
sent them:

```ts
context.subscribe("theme.changed", ({ from, payload }) => {})
```

## Who sent it

`from` describes the sender: the same values for every receiver, whatever
it may see. It is `null` when the sender is no Program, such as a script or
the terminal acting for the owner.

| Field | Is |
| --- | --- |
| `program` | Its Program's `identity` and `name` |
| `process` | The identity of its Process |
| `endpoint` | `"server"` or `"client"` |

```ts
context.answer("open", async ({ from }) => {
  if (from === null) return "a script"
  if (from.program.identity === (await context.program()).identity) return "one of mine"
  return from.program.name
})
```

A message never carries the sender itself. To reach it, find its Process,
which needs permission to see it:

```ts
const sender = await system.process.find(from.process)   // null when you may not see it
sender?.[from.endpoint].publish("welcome")
```

A Process identity is never reused, so it can key what you keep for one
caller.

From outside, listening to an Endpoint or a Service hears what it publishes:

```ts
process.server.subscribe("progress", percent => render(percent))
```

## Three ways to listen

Every source of events in PhreshOS offers the same three:

```ts
const stop = target.subscribe("changed", value => {})   // until you stop
const value = await target.wait("changed")              // the next one
for await (const value of target.events("changed")) {}  // one by one
```

Listening hears what happens from now on. To know the current state, read it
first, then follow its changes. Each way, with its deadline, its end, and
listening to every event at once, is in [Concepts](/docs/concepts#events).

## Ask

A question gets exactly one answer, or fails:

```ts
const notes = await process.server.ask("notes.list")
await process.server.timeout(60_000).ask("report.create")   // ten seconds by default
```

```ts
context.answer("notes.list", () => loadNotes())   // in the Server
```

A question fails when the Server is not available, stops before answering,
throws, or runs out of time.

## When the asker stops waiting

A question carries a `signal`, aborted once its asker stops waiting: its time
ran out, it stopped, or it went away. Stop what no one waits for any more, or
hand the signal to whatever takes one:

```ts
context.answer("page.fetch", async ({ payload, signal }) => {
  signal.addEventListener("abort", () => closePreview())
  const response = await fetch(payload.url, { signal })
  return await response.text()
})
```

An answer given after that reaches no one.

## Types

```ts
const notes = await process.server.ask<Note[]>("notes.list")
```

## More than JSON

Messages and answers carry dates, maps, sets, errors, binary data, and
streams, and they arrive as themselves. A stream arrives as a stream, read as
it comes:

```ts
context.answer("file.read", () => ({ content: fileStream }))   // Server
const { content } = await context.server.ask("file.read")      // Client
```

## Watch what an Endpoint sends

Subscribing to an Endpoint hears only what it publishes from itself, with
no destination. What it sends to a particular Endpoint is seen through its
`traffic`: messages, questions, and, for a Server, its answers.

```ts
process.client.traffic.subscribe("theme.changed", ({ to, payload }) => {})
process.client.traffic.subscribeAsks(({ event, questionId, message }) => {})
process.server.traffic.subscribeAnswers(({ event, questionId, message }) => {})
```

`to` describes where it went, as `from` describes a sender, or is `null`
when it went to no Program, such as an answer to a script. An answer carries its question's `questionId`, and its
`outcome` holds either the `result` or the `error`. Questions and answers
also come one by one through `asks()` and `answers()`.

Traffic only watches: nothing it sees is changed or delayed, and it cannot
answer a question.

## From the terminal

```sh
phresh endpoint ask --process main --program notes --endpoint server --event notes.list
phresh endpoint publish --process main --program notes --endpoint client --event changed --payload '{"value":1}'
phresh endpoint wait --process main --program notes --endpoint client --event changed
```
