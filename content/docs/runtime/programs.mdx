A Program is a piece of software known to the System. It has a stable
identity, owns the resources its runs share, such as files, storage, logs,
and permissions, and is the only place from which its
[Processes](/docs/runtime/processes) are created.

The Program stays the same while its files are updated and its Processes come
and go. That is why durable things belong to it, and live things belong to a
Process.

```ts
const program = await system.program.find("notes")
const process = await program?.createProcess({ client: true })
```

## Find a Program

```ts
await system.program.list()        // every Program you can see
await system.program.list(true)    // installed Programs only
await system.program.find("notes") // one Program, or null
```

`find()` returns `null` both when a Program does not exist and when you are
not allowed to see it, so a lookup never reveals hidden software. See
[Permissions](/docs/system/security/permissions).

```sh
phresh program list
phresh program inspect --program notes
```

## Read its identity

```ts
program.identity     // "notes": lowercase words joined by hyphens
program.name         // "Notes"
program.version      // "1.2.0", or "0.0.0" when not declared
program.description  // string or null
program.server       // { start, service }, or null when not declared
program.client       // { start, service, sandbox, title, size, … }, or null
```

`server` and `client` describe what a new Process starts by default. A `null`
Endpoint cannot be started by any Process of this Program.

```ts
await program.icon("large")   // PNG Blob: "small", "medium" (default), or "large"
await program.agent()         // the Program's agent document, or null
await program.definition()    // the complete definition the Program was created from
```

`definition()` describes what the author declared. It does not include state
the System manages, such as permissions, pinning, or startup.

## Create and manage its Processes

Every Process is created from its Program, because the Program carries the
definition, defaults, storage, and authority that the run needs.

```ts
const process = await program.createProcess({ name: "main", client: true })

await program.processes()            // every live Process
await program.findProcess("main")    // by name or identity
await program.exitProcesses()        // end them all
```

Launch options, naming, and lifetimes are covered in
[Processes](/docs/runtime/processes).

## Use its resources

Resources belong to the Program, so every Process of it sees the same ones,
and they outlive any single run.

| Resource | What it holds |
| --- | --- |
| `program.data` | Durable files |
| `program.cache` | Files that may be deleted to reclaim space |
| `program.store` | Persistent key-value state |
| `program.database` | A writable SQLite database |
| `program.logs` | Captured output of its Endpoints, read-only |
| `program.permissions` | Its effective permissions |

```ts
await program.store.set("theme", "dark")
const rows = await program.database.query("select * from notes")
```

See [Storage](/docs/system/storage), [Logs](/docs/system/logs), and
[Permissions](/docs/system/security/permissions).

## Pin it and start it with the System

The System keeps a small amount of state about each Program, separate from
its definition. It survives updates and ordinary uninstallation, and is
removed only when the Program's storage is purged.

```ts
await program.pin()          // keep it as a favorite in Desktop interfaces
await program.unpin()
await program.pinned()       // boolean

await program.startup.enable({ name: "main", server: true })
await program.startup.disable()
```

Pinning never starts a Process. `startup` stores one launch that the System
runs each time it boots. See
[Start a Process with the System](/docs/runtime/processes#start-a-process-with-the-system).

## Installed and attached Programs

A Program runs in one of two forms:

- **Installed**: its files are copied into the System, and it stays available
  across System restarts.
- **Attached**: it runs directly from a project folder during development, and
  it exists only while the connection that attached it, such as `phresh dev`,
  is open.

Both forms are the same kind of Program. Only where its files live and how
long it exists differ.

```ts
await program.installed()   // whether it has an installed form
```

## Install and uninstall

`install()` and `uninstall()` stream the output of the Program's own install
and uninstall commands:

```ts
for await (const chunk of program.install()) {
  console.log(chunk.stream, chunk.text)
}
```

```sh
phresh install
phresh install notes --run
```

Installing replaces the Program's files. Its live Processes keep running while
the install command runs, and end just before the new files take effect.

After a successful install, the System can start one Process. By default it
uses the `installLaunch` from the definition, and you can override it:

```ts
program.install({ launch: { name: "main", client: true } })  // this launch
program.install({ launch: true })                            // Endpoint defaults
program.install({ launch: false })                           // start nothing
```

`purge` removes data as well:

| Call | Effect |
| --- | --- |
| `install({ purge: true })` | Deletes the previous installed storage before installing |
| `uninstall()` | Removes the installed files; storage and the Program remain |
| `uninstall({ purge: true })` | Also ends its Processes, deletes its storage, and removes the Program |
| `forget()` | Ends its Processes and removes the Program, leaving installed files in place |

Uninstalling a Program that is not installed completes without output.

## Create a Program from a definition

`system.program.create()` registers a new, uninstalled Program from a
definition object or an absolute path to a `program.json`:

```ts
const program = await system.program.create("/path/to/notes/program.json")
```

`forceCreate()` does the same, replacing any Program that already uses that
identity. It keeps that Program's installed files and storage.

Most Programs are created for you by `phresh dev` and `phresh install`. See
[Program configuration](/docs/sdks/core/program-configuration) for what a
definition contains.

## Observe changes

A Program emits events about itself:

```ts
program.subscribe("processCreate", process => {})
program.subscribe("processExit", ({ process, status }) => {})
program.subscribe("pinned", pinned => {})
program.subscribe("permissions", permissions => {})
program.subscribe("uninstall", ({ purge }) => {})
program.subscribe("forget", () => {})
```

`system.program` emits the same kinds of changes for every Program you can
see: `create`, `install`, `uninstall`, `forget`, `pinned`, and `permissions`.

```ts
system.program.subscribe("install", program => {})
```

## Permissions

An Endpoint can always see and manage its own Program. Seeing or managing
another Program requires the `programs` permission for it. See
[Permissions](/docs/system/security/permissions).

## Reference

| Member | Result |
| --- | --- |
| `system.program.list(onlyInstalled?)` | Visible Programs |
| `system.program.find(identity)` | A Program, or `null` |
| `system.program.create(source)` / `forceCreate(source)` | A new uninstalled Program |
| `identity`, `name`, `version`, `description` | Declared identity |
| `server`, `client` | Endpoint declarations, or `null` |
| `icon(size?)`, `agent()`, `definition()` | Declared assets and definition |
| `createProcess()`, `findOrCreateProcess()`, `runProcess()` | Start Processes |
| `processes()`, `findProcess()`, `oldestProcess()`, `newestProcess()` | Find live Processes |
| `exitProcesses()` | End every live Process |
| `data`, `cache`, `store`, `database`, `logs`, `permissions` | Program resources |
| `pin()`, `unpin()`, `pinned()`, `startup` | System-managed state |
| `installed()`, `install()`, `uninstall()`, `forget()` | Installation and removal |
