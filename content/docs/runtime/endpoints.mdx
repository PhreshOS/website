An Endpoint is one of the two roles inside a [Process](/docs/runtime/processes):

- the **Server** runs on the host, keeps working without a browser, and
  answers questions;
- the **Client** is the Program's interface, shown in a Desktop Window.

Each role can be started and stopped on its own while the Process keeps
running. The handle you hold, `process.server` or `process.client`, stays the
same across those starts and stops.

```ts
await process.client.start()
await process.server.ask("status")
```

## One handle, many runs

`process.server` and `process.client` always exist, even when that Endpoint
is stopped or the Program does not declare it. Each time an Endpoint starts,
a new run of its code begins behind the same handle.

This lets you subscribe to an Endpoint, or wait for it, before it starts and
across restarts, without replacing the handle each time.

```ts
await process.client.running()   // whether it runs now
await process.client.isService() // whether the current run is a Service
await process.client.process()   // the owning Process
```

Operations on the handle reject when the Process has exited or when the
Program never declared that Endpoint.

## Start and stop

`start()` makes sure the Endpoint runs. If it already runs, nothing changes.

```ts
await process.server.start()
await process.client.start({ title: "Inspector", size: { width: 520, height: 420 } })
```

The settings you pass apply only when a new run has to be created. They use
the same fields as the [launch](/docs/runtime/processes#create-a-process) of a
Process.

`stop()` makes sure the Endpoint does not run, and releases what its run
held. If it already stopped, nothing changes.

```ts
await process.client.stop()
```

Stopping one Endpoint never exits the Process. For the same reason, you
cannot stop the last running Endpoint: exit the Process instead.

## Wait until it is ready

Starting is not the same as being ready to use. `waitReady()` resolves when
the Endpoint can be used:

- a Client is ready as soon as it runs;
- a Server is ready once its code has started and connected to the System.
  Questions sent before that moment would have nowhere to go.

```ts
await process.server.start()
await process.server.waitReady()
```

The default deadline is ten seconds; pass milliseconds to change it. While the
Process exists, `waitReady()` keeps waiting through a temporary stop. Several
callers waiting at once resolve together, and a call made while the Endpoint
is already ready resolves immediately.

## Observe starts and stops

`lifecycle` reports each time a run starts or stops:

```ts
process.client.lifecycle.subscribe("start", () => {})
process.client.lifecycle.subscribe("stop", () => {})
```

Lifecycle events are kept apart from the Endpoint's own events, so an
application event named `start` or `stop` never collides with them.

## The Server

The Server runs host-side code: background work, file access, network access,
and anything that must continue when no Window is open.

It is the Endpoint you can ask questions. `ask()` waits for the Server to be
ready, sends the question, and resolves with its answer:

```ts
const notes = await process.server.ask("notes.list")
const saved = await process.server.timeout(30_000).ask("notes.save", note)
```

If the Server run stops before answering, the question rejects rather than
moving to a later run. One deadline covers both waiting and answering. See
[Ask a Server](/docs/runtime/communication#ask-a-server).

The Program chooses how its Server runs: as an operating-system command, as a
module in a Node.js Worker, or as a module in a Sandbox with limited host
access. The code and the API are the same in all three. See
[Endpoint execution](/docs/system/security/execution).

If a Server stops unexpectedly, its whole Process ends. See
[Exit a Process](/docs/runtime/processes#exit-a-process).

## The Client

The Client is the Program's interface. Each run is a web page shown in a
Desktop Window, in a sandboxed iframe unless the Program declares
`sandbox: false`.

The System serves the page declaring the Desktop's theme: it adds
`<meta name="color-scheme">` to the page's `<head>` unless the page declares
one itself. The page is then in the Desktop's theme from its first paint, and
the Desktop shows through wherever the page is transparent. To keep following
the theme after it changes, use React UI's
[`DocumentTheme`](/docs/sdks/react-ui/appearance#give-the-page-the-theme).

`process.client.window` is a permanent handle, like the Endpoint handle
itself. Its values are not: each run starts with a fresh Window, set from the
Program's declaration and the settings passed to `start()`. A restarted Client
does not keep the previous run's position or size.

```ts
const window = process.client.window
await process.client.start({ size: { width: 900, height: 640 } })
```

See [Desktop](/docs/system/desktop) for Windows.

### Client memory

Every running Client has a small key-value memory held by the System. It is
shared by all browser views of that run, including after a page reload. A new
Client run starts empty; stopping the Client or exiting its Process ends that
memory. The Client can use `context.memory`, and code holding its Endpoint can
use `process.client.memory`:

```ts
await context.memory.set("tab", "colors")
await context.memory.get("tab")              // "colors"
await context.memory.update("count", current => (Number(current) || 0) + 1)
const stop = context.memory.subscribe("tab", tab => { /* update the interface */ })
stop()
```

`get()` returns `undefined` for an absent key; `entries()` lists all values,
and `delete()` removes one key. Values must be JSON, at most 16 KiB each, with
64 KiB available for all keys and values in one run. `update()` commits a
read-modify-write atomically; its updater should be pure because concurrent
writes can cause it to run again. Through an Endpoint handle, reading a stopped
Client returns no values while writes reject. A new run starts empty. Use
[`program.store`](/docs/system/storage) for durable state.

A Client receives messages but does not answer questions. The same Client can
be open on several Desktops at once, so a question would have no single
Client to answer it. Ask the Server instead.

## Becoming a Service

An Endpoint run marked as a Service can be discovered and reached by other
Programs:

```ts
await program.createProcess({ name: "sync", server: { service: true } })
```

The Service setting applies to one run. It comes from the Program's
declaration unless a launch or `start()` overrides it. See
[Services](/docs/runtime/services).

## Reference

| Member | Result |
| --- | --- |
| `start(launch?)` | Ensures the Endpoint runs |
| `stop()` | Ensures the Endpoint does not run |
| `running()` | Whether it runs now |
| `waitReady(timeout?)` | Resolves when it can be used |
| `isService()` | Whether the current run is a Service |
| `process()` | The owning Process |
| `lifecycle` | `start` and `stop` events |
| `publish(event, payload?)` | Sends a message to the Endpoint; see [Communication](/docs/runtime/communication) |
| `subscribe`, `wait`, `events` | What the Endpoint announces with `context.publish()` |
| `traffic` | What the Endpoint sends; see [Communication](/docs/runtime/communication#observe-traffic) |
| `server.ask(event, payload?)`, `server.timeout(ms)` | Ask the Server a question |
| `client.window` | The Client's Window |
| `client.memory` | Shared key-value memory for the current Client run |
